## PR handoff

The Store now requests a real inline adaptive AdMob banner at the fictional phone billboard's measured width, using Google's official sample app/banner IDs in Debug builds. Go Indie ownership suppresses the native view immediately; unresolved ownership suppresses all banner requests. RevenueCat CustomerInfo is the entitlement authority. The app invalidates RevenueCat's persisted cache before its promise-held launch fetch, so that explicit operation can catch a refund at the next successful launch. Identity-less listener callbacks can upgrade ownership but can never revoke a confirmed owner; only an application-initiated operation can do that. A fresh confirmation splits an open away interval at the entitlement time instead of applying the owner rate retroactively. [`ADMOB_SETUP.md`](./ADMOB_SETUP.md#entitlements-and-consent) owns the full ordering, visibility, and retention contracts.

**Test IDs cannot silently ship on iOS:** the native Xcode release guard rejects missing, malformed, sample, cross-publisher, or archive-drifted IDs captured at prebuild, so archiving a development prebuild fails; release JavaScript validates embedded IDs at startup. The guard uses Expo Constants' pinned Xcode Node wrapper so both consumers share the login-shell and `.xcode.env` layers. Platform-neutral Expo config does not gate non-iOS releases on iOS identifiers. Valid production IDs pass only for the enumerated release environments; an EAS job must carry the exact cloud marker `EAS_BUILD_RUNNER=eas-build`. A local EAS production build deliberately embeds Google samples and the native Release guard refuses it, because live inventory in a developer-machine, non-store binary risks invalid traffic and AdMob account suspension; EAS cloud is the supported release path. A missing or different runner never implies release. There is no test-release bypass. The verified identifiers are committed in the EAS preview and production profiles and pass through the single `config/admob.js` identifier resolution path. Catvertising is not linked into Android builds.

**App Store Connect remains captain-owned:** the captain must answer every App Privacy data-collection, purpose, identity-linkage, and tracking question after reviewing the final archive and production services. The [App Privacy worksheet](PRIVACY_POLICY_DRAFT.md#app-store-connect-app-privacy-worksheet) pairs each question with relevant code evidence without completing the declaration.

**Audience and serving policy:** this is a general-audience implementation. It collects no age, sends no child-directed or under-age-of-consent treatment signal, and requests only non-personalized banners. UMP exposes no supported way to tell whether a prior consent record exists before starting its required session update, so the app starts one shared refresh attempt at launch for everyone, including Go Indie owners, and reuses a successful update for that session. A failed attempt is discarded; only a later measured billboard visibility return for an eligible free user can start another attempt, with no timer or retry loop. A player already known to own Go Indie never receives the automatic consent form or initializes Mobile Ads. If ownership is confirmed while consent or initialization is already in flight, that operation may finish before the post-operation ownership check suppresses the banner. This deliberate window never presents advertising to a confirmed owner. The implementation does not request ATT permission or integrate cross-company tracking or attribution APIs. Public-policy publication and the App Store Connect declaration remain captain-owned. The stale repository metadata draft is retired; the captain-owned listing must retain its advertising and Go Indie removal claims.

Under Fabric with RN-GMA 16.5.0, recycled native views can forward delayed callbacks without request identity; this accepted limitation requires native identity or a vendor change for a durable fix. The no-new-request-during-scroll behavior depends on **Automatic refresh** remaining disabled for the banner unit, as verified in AdMob on 2026-09-19. Keeping the loaded creative mounted avoids scroll flicker; JavaScript cannot synchronously close the native movement gap, and a durable fix requires native-side occlusion enforcement.
